# Инструкция: собрать бота бесплатно

Итоговая схема, которую собираем:

```
GitHub Actions (бесплатно)          Ваш компьютер
        │                                │
   среда 10:00 МСК                  когда удобно
        │                                │
   рассылка в Telegram            создание заказа
   + CSV с закупкой                в МойСклад
```

Почему так: рассылка работает сама и ничего не стоит. Заказ требует токена
МойСклад с правами на запись, и держать его в чужом облаке незачем — команда
запускается локально, когда закупка действительно нужна.

Время на настройку: **около 20 минут**.

---

## Шаг 0. Что понадобится

| Что | Где взять | Стоимость |
|---|---|---|
| Python 3.10+ | python.org | 0 ₽ |
| Аккаунт GitHub | github.com | 0 ₽ |
| Токен МойСклад | Настройки → Приложения | входит в подписку |
| Токен WB | Кабинет WB → Настройки → Доступ к API | 0 ₽ |
| Бот в Telegram | @BotFather | 0 ₽ |

Токен МойСклад: **Настройки → Приложения → Создать токен**. Права — чтение
(для рассылки). Если планируете создавать заказы тем же токеном, нужны и
права на запись.

---

## Шаг 1. Проверить локально

До всякого GitHub убедитесь, что расчёт вообще работает на ваших данных.
Это самое важное — если здесь что-то не так, в облаке будет то же самое.

```bash
cd stockbot
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Сначала на демо-данных, без токенов:

```bash
python tools/make_mock.py > /tmp/dump.json
python main.py dry-run --dump /tmp/dump.json
```

Должен напечататься дайджест. Если да — переходим к настоящим данным.

### Настройте config.local.yaml

В `config.yaml` лежат демо-поставщики. Реальные кладите в отдельный файл —
он в `.gitignore` и в публичный репозиторий не попадёт:

```yaml
# config.local.yaml
suppliers:
  "ООО Ромашка":              # имя должно совпадать с МойСклад
    lead_time_days: 3
    pack_qty: 6
    contact: "@manager"
  "ИП Иванов":
    lead_time_days: 14
    pack_qty: 3
```

Файл накладывается поверх `config.yaml`, ничего не затирая.

### Первый прогон на живых данных

```bash
export MOYSKLAD_TOKEN='ваш_токен'
python main.py dry-run --csv digest.csv
```

Проверьте в выводе три вещи:

| Что смотреть | Норма | Если не так |
|---|---|---|
| `Карточки WB найдены по баркоду: N из M` | близко к M | не заполнены `ean13`/`gtin` в МойСклад |
| `Не успевает к началу окна` | немного позиций | сроки поставки в конфиге неверные |
| `К заказу: N шт по M позициям` | десятки, не тысячи | проверьте `folder_map` и склад |

## Шаг 2. Создать бота в Telegram

1. Написать **@BotFather** → `/newbot` → имя → получить токен вида
   `7123456789:AAH...`
2. Написать своему боту любое сообщение (иначе он не сможет вам писать).
3. Узнать свой `chat_id`:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getUpdates"
```

В ответе найдите `"chat":{"id":123456789}` — это и есть ваш chat_id.
Для группы id отрицательный, начинается с `-100`.

## Шаг 3. Выложить на GitHub

**Репозиторий должен быть публичным.** Это не прихоть: в приватном
репозитории на бесплатном плане GitHub планировщик (`cron`) не запускается
вообще — молча, без единой ошибки. Секреты при этом хранятся отдельно и в
код не попадают.

```bash
cd stockbot
git init
git add .
git commit -m "digest bot"

# создайте пустой репозиторий на github.com, затем:
git remote add origin https://github.com/ВАШ_ЛОГИН/stockbot.git
git branch -M main
git push -u origin main
```

Перед `git add` убедитесь, что не утекают секреты:

```bash
git status --short          # config.local.yaml и .env быть не должно
```

---

## Шаг 4. Добавить секреты

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
|---|---|
| `MOYSKLAD_TOKEN` | токен МойСклад |
| `WB_TOKEN` | токен WB |
| `TELEGRAM_BOT_TOKEN` | от @BotFather |
| `TELEGRAM_CHAT_IDS` | `123456789` (несколько — через запятую) |

Имена должны совпадать **точно**, включая регистр.

---

## Шаг 5. Проверить запуск вручную

**Actions** → слева `weekly-digest` → кнопка **Run workflow** → **Run**.

Через 1–2 минуты должно прийти сообщение в Telegram: сводка, блоки по
поставщикам, CSV-файл.

Если нет — смотрите лог запуска, там будут понятные ошибки:

| Ошибка | Причина |
|---|---|
| `Нужен TELEGRAM_BOT_TOKEN` | секрет не добавлен или имя с опечаткой |
| `401: токен невалиден` | токен МойСклад истёк |
| `403: у WB-токена нет категории «Контент»` | перевыпустить токен WB с этой категорией |
| `Склад «Основной склад» не найден` | имя склада в `config.yaml` не совпадает |

Пришло сообщение — расписание работает. Дальше оно само.

Расписание задано в `.github/workflows/digest.yml`:

```yaml
- cron: "0 7 * * 3"     # среда 07:00 UTC = 10:00 МСК
```

Москва — UTC+3 круглый год, пересчёта на летнее время не требуется.
Строка должна быть в ветке `main`, иначе не сработает.

## Шаг 6. Создание заказа (локально)

Раз в неделю, после дайджеста, когда решили, что заказывать.

Сначала посмотреть, что будет создано — **без обращения к API на запись**:

```bash
python main.py order all --dry
```

Потом создать черновики:

```bash
export MOYSKLAD_TOKEN='ваш_токен'
python main.py order Текстиль       # один поставщик, по части имени
python main.py order all            # все сразу
```

В ответе — номер документа и ссылка:

```
✓ ООО Текстиль-Опт: черновик «Автозаказ 18.11.2026», 5 поз., 30 шт
  https://online.moysklad.ru/app/#purchaseorder/edit?id=...
```

**Документы создаются непроведёнными.** Проверьте цены и количество,
проведите вручную. Заказ с ценой 0 — это нормально: цены подтянутся из
карточек товара при проведении.

Ссылки на WB при создании заказа не запрашиваются — это заметно быстрее.

## Что делать регулярно

| Когда | Что |
|---|---|
| Среда 10:00 | приходит дайджест сам |
| После дайджеста | `python main.py order all --dry`, потом без `--dry` |
| Раз в месяц | проверить, что в Actions нет ошибок |
| Раз в 60 дней | GitHub отключает cron после 60 дней без коммитов — придёт письмо, нажать **Enable workflow** |

## Если что-то сломалось

**Дайджест не пришёл в среду.**

1. Actions → был ли запуск? Если нет — репозиторий приватный (см. шаг 3)
   либо workflow не в ветке `main`.
2. Запуск был, но упал → смотрите лог, таблица ошибок в шаге 5.
3. Запуск прошёл, сообщения нет → проверьте, что вы написали боту, и что
   `chat_id` правильный.

**В дайджесте мало позиций / пусто.** Проверьте `warehouse` в `config.yaml`
и `folder_map` — если папки в МойСклад называются иначе, позиции не
попадут в расчёт. Запустите `dry-run` локально: там видно, сколько SKU
просмотрено.

**Заказ создаётся, но без поставщика.** Поставщик ищется по атрибуту
«Поставщик» в карточке товара, затем по последней приёмке. Если в МойСклад
ни того, ни другого нет — заполните атрибут.

## Сколько это стоит

| Компонент | Стоимость |
|---|---|
| GitHub Actions (публичный репозиторий) | 0 ₽, минуты не ограничены |
| Telegram Bot API | 0 ₽ |
| WB Content API | 0 ₽ |
| МойСклад | ваша текущая подписка |

Запуск занимает около минуты раз в неделю. Год работы — примерно час
машинного времени, бесплатно с большим запасом.

---

## Если понадобится бот с командами

Схема выше даёт только рассылку: `/digest` и `/order` в Telegram не
работают, потому что между запусками бот не существует.

Если нужны команды в любой момент:

```bash
python main.py run          # на постоянно включённом ПК или сервере
```

Подойдёт старый ноутбук, Raspberry Pi или бесплатный тир Oracle Cloud.
Подробности — в `DEPLOY.md`.
