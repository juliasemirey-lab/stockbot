# Дайджест пополнения склада

Раз в неделю присылает в Telegram: что закупить, чтобы хватило на следующую неделю.

## Как считается

```
продажи в день  = продано за 28 дней / 28
спрос за неделю = продажи в день × 7 × сезонный коэффициент
страховой запас = 1.65 × разброс продаж × √7
остаток к началу окна = доступно − продажи в день × дни до понедельника
заказать        = спрос + страховой − остаток к началу окна − ожидание
```

**Окно — следующая неделя, с понедельника.** Если дайджест пришёл в
субботу 14-го, считаем на 16–22 ноября. За двое суток до понедельника
часть товара уйдёт, поэтому потребность считается не от сегодняшнего
остатка, а от остатка к началу окна.

**Доступно** — остаток «Основного склада» минус резерв на нём же.

**Ожидание** (`inTransit`) — товар в пути на склад. В «Доступно» не входит:
продать его пока нельзя. Из потребности вычитается, иначе закажете лишнее.

**Продажи** — все документы отгрузки и розничные продажи, склад не
разбирается: товар ушёл с любого склада, значит спрос состоялся.
Возвраты **не вычитаются**: по схеме комиссионера отгрузка на маркетплейс —
это уже продажа, а возврат приходит отдельным документом и оприходуется
обратно на склад, то есть уже сидит в остатке.

## Почему 28 дней, а не 30

28 — ровно четыре недели: одинаковое число понедельников, суббот и
воскресений. В 30 днях два лишних дня приходятся на разные дни недели,
и средний дневной темп смещается. Меняется в `config.yaml`.

## Источники

| Что | Откуда |
|---|---|
| Товары, баркоды, поставщик | `/entity/product` |
| Остаток, резерв, ожидание | `/report/stock/bystore` |
| Продажи | `/entity/demand` + `/entity/retaildemand` |
| Имена поставщиков | `/entity/counterparty` + `/entity/organization` |

**Важно про `limit`.** МойСклад раскрывает вложенные поля только при
`limit≤100`. При большем лимите `expand` молча игнорируется — позиции
документов приходят пустыми, папки товаров без имён. Везде, где нужен
`expand`, стоит `page=100`.

**Склад ищется по полю `name`** внутри `stockByStore`, а не по ссылке:
ссылка может прийти с query-хвостом, и сравнение по ней не проходит —
тогда остаток оказывается нулевым у всего склада.

## Сопоставление с Wildberries

Только по баркоду. Артикул не используется вообще: он в МойСклад не
совпадает с WB, и поиск по нему ведёт на чужой товар.

Баркоды бывают длиной 13 и 14 знаков — в МойСклад и на WB одинаково.
Берутся все баркоды карточки, сравнение посимвольное. Ведущие нули не
обрезаются, ничего не добивается: `0001234567890` и `1234567890` — разные коды.

| Ситуация | Что делаем |
|---|---|
| Баркод найден | ставим ссылку |
| Два баркода товара ведут на разные карточки | ссылки нет, в лог |
| Баркод в двух карточках WB | ссылки нет, в лог (признак битого индекса) |
| Не найден | ссылки нет, в лог |

Индекс карточек кэшируется на диск (`.wb_cache.json`, `cache_days` дней):
обходить тысячи карточек при каждом запуске — это минуты.

## Что в сообщении

```
🧵 Закупка на неделю 14–20 ноября

4 позиции, 15 шт. Кончатся в ближайшие дни: 2 — если не заказать
сейчас, часть недели простоим без товара.

🔥 Горит

Джинсы Miller · синий · 32
осталось 0 · закончился · → нужно 10   ООО Стиль

⏳ Дотянет до конца недели, но впритык

Блузка Adele · белый · S
осталось 8 · хватит на 7 дней · → нужно 1   ИП Иванова

📦 По поставщикам

ООО Стиль — 10 шт / 1 позиция
ИП Иванова — 4 шт / 2 позиции
```

Сортировка по срочности: сначала то, что кончится. Ссылка идёт голым
адресом без подписи. В сообщении первые 15 позиций, полный список — в CSV.

## Запуск

```bash
pip install -r requirements.txt
export MOYSKLAD_TOKEN='...'
python main.py dry-run     # напечатать в консоль
python main.py sources     # что вернул каждый источник
python main.py once        # отправить в Telegram
```

Для `once` нужны ещё `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS`.
Для ссылок WB — `WB_TOKEN` с категорией «Контент» из того же кабинета,
где живут карточки.

## Настройка

| Параметр | Смысл |
|---|---|
| `warehouse` | Склад для доступного остатка. ФБО не указывать |
| `velocity_window_days` | Окно оценки продаж, по умолчанию 28 |
| `horizon_days` | На сколько дней вперёд считаем |
| `service_z` | Страховой запас. 1.65 ≈ 95% |
| `profiles` | Сезонность по месяцам и кратность упаковки |
| `season_map` | Ключевые слова → профиль, от специфичного к общему |
| `top_n_in_chat` | Сколько позиций в сообщении |
| `wildberries.cache_days` | Срок жизни кэша карточек WB |

Сезонных профилей четыре: зима, демисезон, лето, трикотаж. Ваша категория
«Верхняя одежда» расщепляется по названию товара: «Шуба» → зима,
«Тренч» → демисезон. Ключи проверяются по порядку, поэтому «шуба» стоит
раньше «куртки».

## Развёртывание

Репозиторий должен быть **публичным**: в приватном на бесплатном плане
GitHub не запускает расписание. Секреты в Settings → Secrets:
`MOYSKLAD_TOKEN`, `WB_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS`.

Расписание — среда 10:00 МСК, в `.github/workflows/digest.yml`.
Диагностика — вручную через `.github/workflows/sources.yml`.
