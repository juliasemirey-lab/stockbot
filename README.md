# Дайджест пополнения склада

Раз в неделю присылает в Telegram: по каким товарам не хватает запаса
на следующую неделю и сколько штук докупить.

## Как считается

```
продажи в день  = продано за 28 дней / 28
спрос за неделю = продажи в день × 7 × сезонный коэффициент
страховой запас = 1.65 × разброс продаж × √7
заказать        = спрос + страховой − доступно
```

**Доступно** — остаток основного склада минус резерв.

Продажи берутся со **всех** складов: товар, проданный через FBS или ФБО,
всё равно нужно восполнить. Доступный остаток — только с основного:
на ФБО товар заморожен под конкретную отгрузку и в покрытие спроса
не идёт.

## Источники — два отчёта МойСклад

| Что | Основной путь | Запасной |
|---|---|---|
| Остаток, резерв, доступно | `/report/stock/all` с фильтром по складу | `/report/stock/bystore` |
| Продажи за период | `/report/turnover/all` | `/report/sales/byproduct`, `/report/profit/byproduct`, документы отгрузки |

Пустой ответ не считается успехом: если отчёт ответил `200 OK`, но без
строк, программа идёт к следующему источнику. Последний рубеж — обход
документов отгрузки с догрузкой позиций по ссылкам.

Обход документов отгрузки не используется: за месяц их бывает около
двух тысяч, и это две тысячи запросов вместо одного.

## Запуск

```bash
pip install -r requirements.txt
export MOYSKLAD_TOKEN='...'
python main.py dry-run          # напечатать в консоль
python main.py once             # отправить в Telegram
```

Для `once` нужны ещё `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS`.

Если дайджест пишет «заказывать нечего», запустите диагностику:

```bash
python main.py sources
```

Она покажет по каждому источнику продаж, что он вернул: сколько строк,
сколько штук, какие поля. По этому видно, работает ли отчёт и в каком
поле лежит количество.

## Что в сообщении

```
Время пополнять склад!

Товары: 412 шт. по 37 позициям

Купальник Sol · чёрный · M
Доступно 2 · хватит на 1 дн. · заказать 12

Блузка Adele · белый · S
Доступно 1 · хватит на 0 дн. · заказать 10
```

В сообщении первые 15 позиций, полный список — в CSV-приложении.

## Настройка

`config.yaml`:

| Параметр | Смысл |
|---|---|
| `warehouse` | Склад, с которого пополняем. ФБО не указывать |
| `velocity_window_days` | За сколько дней оценивать скорость продаж |
| `horizon_days` | На сколько дней вперёд считать потребность |
| `service_z` | Страховой запас. 1.65 ≈ покрытие 95% случаев |
| `folder_map` | Папка МойСклад → категория |
| `categories` | Сезонность по месяцам и кратность упаковки |

**Важно про `folder_map`.** Если папки в МойСклад называются иначе, все
товары попадут в категорию `default` — без сезонности. Названия должны
совпадать частично, регистр не важен: ключ `"купальник"` поймает папку
«Купальники слитные». Самое длинное совпадение выигрывает.

Проверить, что подхватилось: в сообщении при неверной категории сезон
не применяется, и потребность выглядит ровной круглый год.

## Развёртывание на GitHub Actions

Репозиторий должен быть **публичным**: в приватном на бесплатном плане
GitHub не запускает расписание вообще. Секреты в Settings → Secrets:
`MOYSKLAD_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS`.

Расписание — среда 10:00 МСК, в `.github/workflows/digest.yml`.
