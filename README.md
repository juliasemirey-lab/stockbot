# Дайджест пополнения склада

Каждую среду в 10:00 МСК присылает в Telegram, что закупить на следующую
неделю. Источник данных — МойСклад. Маркетплейсы не опрашиваются.

## Что считает

```
доступно = основной склад + «Ярмарки» − резервы
расход   = отгрузки с основного + розница с основного
           + перемещения с основного (буферы ФБО, Ярмарка)
           − перемещения обратно на основной
           − возвраты покупателей, за 28 дней
заказать = расход/28 × 7 × сезон + страховой − доступно − в пути
```

**Отгрузки со складов-спутников в расход не идут.** Это не потеря основного склада:
отгрузка с буфера ФБО уже учтена раньше — как перемещение на буфер в момент, когда
товар физически ушёл со склада. Продажа с Ярмарки тоже не считается отдельно:
её покрывает нетто-перемещение (увезли минус вернули).

**«Ярмарки» входят в покрытие, но не в показываемый остаток.** Товар наш и
вернётся, поэтому заказать меньше можно. Но физически он не на полке,
кладовщик его не найдёт, на маркетплейс он не выгружается — поэтому в
сообщении это отдельное слагаемое `0+1⛺`.

## Два яруса

В сообщение попадает только то, по чему нужно действовать сейчас.

**🔥 Горит** — позиция ходовая И сетка реально вымылась И дефицит стоит того,
чтобы ехать к поставщику. Позиция — это полное название без размера плюс
поставщик. Цвет отдельной модификацией не является: он записан прямо в
названии, поэтому «моделью» позицию называть неверно. Отдельно режется
только размер.

**Срочность считается БЕЗ страхового запаса.** Позиция горит, когда товар
кончается на этой неделе, а не когда просела подушка. Из-за просевшей подушки
к поставщику не бегут — это плановая докупка. Заказ при этом всё равно
считается с подушкой: её надо восполнять.

| Условие | Значение |
|---|---|
| размеров в позиции | ≥ 3 |
| доля реально вымытых размеров | ≥ 70% |
| продажи позиции | ≥ 75-го квартиля когорты |
| реальный дефицит | ≥ 6 шт |

Порог по продажам не абсолютный, а от когорты: растут продажи — растёт и он.
На ноябрьских данных это 13 позиций из 215.


**Всё остальное** — в CSV, но в сообщении остаётся строка с весом файла
(сколько позиций, сколько штук, сколько с вымытой сеткой). Иначе файл
не откроют.

## Расписание

`cron: "0 7 * * 3"` — 07:00 UTC, это 10:00 МСК по средам.

Окно — со следующего понедельника, а не с завтрашнего дня: дайджест в среду
14-го считает закупку на 16–22.

## Запуск

```bash
pip install -r requirements.txt

export MOYSKLAD_TOKEN=...        # обязателен
export WB_TOKEN=...              # необязателен: только ссылки на карточки
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_IDS=...

python main.py dry-run           # напечатать и сохранить digest.csv
python main.py sources           # диагностика источников
python main.py once              # отправить в Telegram и выйти
```

`dry-run` пишет `digest.csv`. Без `WB_TOKEN` всё работает, просто без ссылок.

## Настройка

`config.yaml`:

| Ключ | Смысл |
|---|---|
| `warehouse` | основной склад — его остатки считаем |
| `yard_warehouse` | склад «Ярмарки», пустая строка — не учитывать |
| `velocity_window_days` | окно оценки расхода (28) |
| `horizon_days` | на сколько считаем потребность (7) |
| `service_z` | страховой запас, 1.65 ≈ 95% сервиса |
| `hot_size_min`, `hot_share`, `hot_quantile`, `hot_min_qty` | порог 🔥 |
| `profiles` | сезонные коэффициенты по месяцам |
| `season_map` | ключевые слова → профиль |

## Известные ограничения

**Остатка на физическом ФБО не видно.** Дайджест не знает, сколько товара
лежит на складах маркетплейса. Поэтому позиции, которые уходят на ФБО,
выглядят как дефицит своего склада. Так и задумано: это плановая закупка
под партию, менеджер решает по факту остатков на маркетплейсе.

**Сезонность работает только там, где её видно по названию.** «Купальник»
и «дубленка» распознаются, артикул без слова — нет. Пока номенклатура не
приведена в порядок, такие позиции считаются всесезонными.

**Возвраты вычитаются, но только по `/entity/salesreturn`.** Если возврат
оформлен как отрицательная отгрузка, он вычтется дважды.

## Проверка, которую стоит делать раз в месяц

```
начальный остаток основного
+ приёмки + перемещения на основной
− отгрузки − перемещения с основного
= конечный остаток основного
```

Если не сходится — где-то потерян документ: забыли приёмку, провели
отгрузку не тем складом, оформили возврат как отгрузку. Расхождение в
балансе всегда означает ошибку в учёте, а не в формуле.
